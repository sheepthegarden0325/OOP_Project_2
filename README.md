### 03/Sep/2026
오늘 물어본 내용: 

1. Resource 는 게임에서 인벤토리 같은건가? 
만약에 맞다면 인벤토리는 네크로멘서에 의해 생성되고 관리되고 사용되는 composition 관계가 되어야 한다.

튜터의 답변은 꼭 정해진 방법은 없으나 필드에 있는 체스트를 생각해보면 체스트는 꼭 어떤 네크로멘서에게 소속된 것은 아니지만 인벤토리를 갖고있다. 그러므로 선택은 내게 달려있지만 composition이던 aggregation이던 구현이 가능해야한다.

2. Undead 의 종류가 4가지가 있는 걸로 알고 있는데 이를 상속관계로 구현해야하는가?

답변: 가능하다. 현제로써는 아직 상속관계를 배우지 않아서 그렇게 구현하지는 않지만 각각의 언데드가 종류별로 각각의 고유 스텟을 갖고있는 관계로 상속을 통한 구현이 유리한 점이 있다. 특히나 프로젝트 구현에 정해진 방법은 없으므로 내가 원하는 방식으로 구현하길 바란다고 답변했다.

3. constructor에 꼭 parameters가 필요한가?
    만약에 리소스를 인벤토리로 본다면 인벤토리는 생성시에 비어있어야 한다.

답변: 그것 역시 내 선택이다. 아까와 같은 예로 만약에 필드에 있는 체스트를 기준으로 생각하자면 체스트는 아이템이 차있는 상태여야한다. 그러나 이것을 constructor에서 처리할 필요는 없다. 한가지 예로 튜터는 상자의 인벤토리를 빈 상태로 생성한 뒤에 각 아이템을 populate하는 방법을 제안했다. 만약 이 경우라면 체스트 클래스를 따로 만들어서 체스트가 리소스 생성시 populate 할 수 있을 것이다. 
만약에 인벤토리는 생성부터 아이템을 가질 수 있다라고 가정한다면 컨스트럭터에 음수나 int 형태가 아닌 아이템 quantity 는 입력될 수 없도록 validation을 추가해야한다.
